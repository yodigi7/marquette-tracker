## 1. Prerequisites

### 1.1 Install pnpm (once, user's machine)

```bash
npm install -g pnpm
pnpm --version        # expect >= 10
```

Fallback if npm-install misbehaves: `corepack enable pnpm && corepack prepare pnpm@latest --activate` (Node 22 ships corepack).

### 1.2 pnpm 10 postinstall policy (IMPORTANT)

pnpm ≥10 blocks dependency `postinstall` scripts by default — this breaks `esbuild` (needed by Vite/shadcn tooling). Fix once at scaffold time by adding to `package.json`:

```json
"pnpm": {
  "onlyBuiltDependencies": ["esbuild"]
}
```

Commit note: if the build ever fails with "esbuild: Command failed", re-check this key.

**Verify:** `package.json`, `vite.config.ts`, `tsconfig*.json`, `eslint.config.js`, `index.html`, `public/vite.svg`, `src/` tree exist. Keep `.gitignore` from template.

### T4 — Path alias `@/` (single source of truth)

Per shadcn v4 docs the alias must exist in **three places** (both tsconfigs + vite):

1. `tsconfig.json`: `"compilerOptions": { "baseUrl": ".", "paths": { "@/*": ["./src/*"] } }`
2. `tsconfig.app.json`: same block (Vite splits configs — misses here cause "Cannot resolve @/components").
3. `vite.config.ts`:
   ```ts
   import path from "path";
   import tailwindcss from "@tailwindcss/vite";
   import react from "@vitejs/plugin-react";
   import { defineConfig } from "vite";

   export default defineConfig({
     plugins: [react(), tailwindcss()],
     resolve: { alias: { "@": path.resolve(__dirname, "./src") } },
   });
   ```
4. `pnpm add -D @types/node` (for `path`/`__dirname` in the config).

**Alternative considered:** `vite-tsconfig-paths` — rejected; explicit alias keeps config readable and the shadcn CLI happy.

### T5 — shadcn/ui init + components

```bash
pnpm dlx shadcn@latest init --base-color zinc --defaults --yes
```

> Troubleshooting: if the CLI complains it can't find `src/index.css` or the `app/` dir, run `pnpm dlx shadcn@latest init` interactively and answer: style=default base color=zinc CSS variables=yes. ### T6 — PWA (`vite-plugin-pwa`)

```bash
pnpm add -D vite-plugin-pwa @vite-pwa/assets-generator
```

**Manifest + SW in `vite.config.ts`:**

```ts

plugins: [
  react(),
  tailwindcss(),
  VitePWA({
    registerType: "autoUpdate",
    includeAssets: false, // picked icons explicitly below
    manifest: {
      name: "Marquette Tracker",
      short_name: "Marquette",
      description:
        "Offline-first fertility tracker using the Marquette Method with the ClearBlue Fertility Monitor.",
      theme_color: "#0c0a09",
      background_color: "#fafaf9",
      display: "standalone",
      start_url: "/",
      lang: "en",
      categories: ["health", "lifestyle"],
      icons: [
        { src: "pwa-192.png", sizes: "192x192", type: "image/png" },
        { src: "pwa-512.png", sizes: "512x512", type: "image/png" },
        { src: "maskable-512.png", sizes: "512x512", type: "image/png", purpose: "maskable" },
        { src: "apple-touch-icon-180.png", sizes: "180x180", type: "image/png" },
      ],
    },
    workbox: { clientsClaim: true, skipWaiting: true },
  }),
];
```

**Icons:** generate temporary placeholders from a simple SVG source (e.g. solid rounded square + "M" glyph) — this can be the logo refined later:

```bash
pnpm dlx @vite-pwa/assets-generator --preset minimal-2023 public/icon.svg
```

(mwrite the output PNGs into `public/`, plus `apple-touch-icon-180.png`. Fallback if the generator chokes: move the SVG fields in and ship `public/icon.svg` only — Chrome accepts SVG manifest icons; note iOS install will lack an icon until PNGs are added.)

**Dev-mode behavior:** `devOptions.enabled: false` (default) — SW + manifest only in `pnpm build`/`preview`. Prevents stale-cache surprises while developing.

**vite-env.d.ts:** add `/// <reference types="vite-plugin-pwa/client" />` if we register SW explicitly — with `registerType: "autoUpdate"` the plugin registers itself; keep the reference only if we add manual install-prompt logic (do so only if simple: `useRegisterSW` in `src/app/pwa-controller.ts` is out of scope for M1; make a note).

### T7 — Vitest harness

```bash
pnpm add -D vitest jsdom @testing-library/react @testing-library/jest-dom @testing-library/user-event fake-indexeddb
```

Key design decision: **dedicated `vitest.config.ts`** that does NOT import the app's Vite plugins (tailwind/PWA) — Vitest 4 reads `vite.config.ts` by default and the PWA plugin config is a noisy inside it:

```ts
// vitest.config.ts
import { defineConfig } from "vitest/config";
import path from "path";

export default defineConfig({
  resolve: { alias: { "@": path.resolve(__dirname, "./src") } },
  test: {
    environment: "jsdom",
    globals: false,
    setupFiles: ["./src/test/setup.ts"],
    include: ["src/**/*.{test,spec}.{ts,tsx}"],
  },
});
```

- `src/test/setup.ts`:
  - `import "@testing-library/jest-dom/vitest";`
- Engine tests (Milestone 2) will use `// @vitest-environment node` per-file so the math layer runs in pure Node — jsdom default for stores/components.
- `fake-indexeddb` dev dep is _declared now_; used in Milestone 3 for Dexie repository tests.
- Smoke test to prove the harness: `src/core/engine/__tests__/smoke.test.ts` with one trivial `expect(1+1).toBe(2)` + one node-env-marked file.
