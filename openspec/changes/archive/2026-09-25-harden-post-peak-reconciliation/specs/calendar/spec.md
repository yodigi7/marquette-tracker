# Spec Delta

## MODIFIED Requirements

### Requirement: Calendar reflects reconciled post-Peak tails

The Calendar SHALL show only the generated records that are currently eligible under the active fill mode, post-Peak setting, cycle boundary, and reconciliation state when the fertile-window algorithm is enabled. Missing dates before an `after-user-low` anchor SHALL remain blank, while eligible generated records SHALL be shown with their stored Low marker and derived status. When the algorithm is disabled, the Calendar SHALL omit all autogenerated records from cells, dialogs, and derived presentation while continuing to show user-authored records.

#### Scenario: User-anchor mode leaves earlier gaps blank

- **GIVEN** the active mode is `after-user-low` and the first qualifying user Low occurs after gaps in the configured post-Peak tail
- **WHEN** the Calendar renders that cycle
- **THEN** dates before the user Low remain without generated records
- **AND** eligible generated dates after the user Low are shown

#### Scenario: New Menses closes the displayed tail

- **WHEN** the user backfills a Menses day that changes the cycle boundary
- **THEN** the Calendar re-renders the affected cycle without stale generated tail records
- **AND** the new Menses day begins the new cycle visually and structurally

#### Scenario: Future dates are not generated

- **WHEN** the Calendar reconciles an open cycle
- **THEN** no future cell receives an autogenerated record
- **AND** future cells remain subject to the existing future-date entry restriction

#### Scenario: Algorithm-off mode hides inferred rows

- **GIVEN** autogenerated post-Peak records exist in storage
- **WHEN** the fertile-window algorithm is disabled and the Calendar renders
- **THEN** no inferred Low dot, assumed marker, status, or inferred dialog content is shown
- **AND** user-authored records remain visible and editable
