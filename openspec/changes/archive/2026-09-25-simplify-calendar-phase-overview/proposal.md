# Proposal

## Why

The Calendar currently asks each day cell to communicate too many independent visual layers at once: four derived statuses, source and forecast cues, multiple raw-data markers, and inferred-data provenance. The resulting cells and flat legend are difficult to scan, especially on narrow mobile viewports, even though the underlying records and detail surfaces are already comprehensive.

The Calendar should become a fast phase-first overview while preserving the full data model, day-entry flow, Status view, and an optional full-detail presentation.

## What Changes

- Make the default Calendar use the simplified human-facing categories `Before`, `Fertile`, and `After`, collapsing `post-peak` and `post-calendar` in the default presentation while retaining their precise meaning in detail surfaces.
- Add a compact current-cycle summary strip showing cycle number, cycle day, simplified status, and the current monitor reading when available, with a clear logging-only state when interpretation is disabled.
- Represent menses with a bottom cell stripe instead of a competing menses dot.
- Use one larger monitor marker shape and encode Low, High, and Peak by color; keep the exact reading available in the summary, day details, and accessible labels.
- Represent inferred/autogenerated records with an asterisk beside the date number instead of a separate assumed-data marker dot.
- Replace the flat default legend with a short, grouped legend for the simplified statuses, menses stripe, monitor readings, and assumed-data asterisk.
- Provide or coordinate with a full-detail presentation that can expose the richer existing indicators on demand, without changing stored data or interpretation.
- Preserve all existing entry, editing, future-date, algorithm-disabled, forecast, and provenance behavior.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `calendar`: Add the phase-first summary, simplified status presentation, menses stripe, date-adjacent assumed marker, grouped default legend, and full-detail display behavior while retaining the existing day-entry and data contracts.
- `fertility-visuals`: Adjust the shared Calendar visual vocabulary so the default view uses a smaller, phase-first legend and marker hierarchy while preserving theme contrast, predictive meaning, and the shared treatments used by other surfaces.

## Impact

- Calendar presentation and tests in `src/features/calendar/`, including the grid/day cell, legend, and any summary component.
- Shared visual mappings and tokens in `src/lib/fertility-visuals.ts` and `src/index.css` where the simplified Calendar treatment requires them.
- Display-mode coordination with the legend visibility work tracked in GitHub issue #15; this change must not introduce a competing visibility model.
- No changes to the pure Marquette engine, fertile-window rules, cycle placement, persisted DayRecord/Cycle data, or backup format.
- No new runtime dependency is expected.

The completed dark-mode fertility-visual change is the visual baseline; this change should be implemented and reviewed alongside it rather than reintroducing light-only treatments.
